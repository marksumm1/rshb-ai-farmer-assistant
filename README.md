# Своё Родное: ИИ-помощник роста фермера

Демопрототип для IT-кейса №1 программы РСХБ.Цифра (2026). ## 🌱 Live Demo

[🚀 Открыть ИИ-помощника роста фермера](https://marksumm1.github.io/rshb-ai-farmer-assistant/dist/index.html)

## Сценарий

Фермер каждый день решает, какие карточки улучшить, какие скидки проверить, кого вернуть и какие остатки пополнить. Помощник показывает три объяснимых приоритетных действия на основе продаж, карточек, акций и обезличенных агрегатов покупателей. Каждое действие объясняет проблему, ожидаемый эффект и источники информации. Решение подтверждает фермер.

Прототип находится в папке dist: достаточно открыть index.html. Нет API-ключей и внешних сервисов. Все данные синтетические; решения и изменения хранятся только в браузере пользователя (localStorage).

## Реализовано

1. Интерактивный веб-экран «Сегодня» с тремя рекомендациями, рассчитанными и отсортированными алгоритмом.
2. Для каждого действия: обоснование, данные, формула эффекта на 7 дней, коэффициент качества и переход к данным.
3. Подтверждение через отдельное окно с чекбоксом; запись в журнале. Внешние действия не выполняются.
4. Редактирование карточки товара, цены, скидки, остатков; автоматический пересчёт рекомендаций.
5. CRM-сегменты и исключения из рассылок: согласие, отписка и ограничение частоты.
6. Методология и интеграционный план внутри приложения; выгрузка демо-отчёта в JSON.

## Детекторы

| Проблема | Сигнал | Порог в демо |
| --- | --- | --- |
| Недозаполненная карточка | Большой трафик, низкая конверсия, пропуски в карточке | от 100 просмотров, готовность менее 90% |
| Неактивные клиенты | Не покупали 45+ дней | действительное согласие, нет отписки и недавних сообщений |
| Низкая маржа | Высокая скидка на популярный товар | скидка от 15%, маржа менее 10% цены |
| Дефицит | Остаток ниже ожидаемого спроса на неделю | продажи за 30 дней доступны |

## Алгоритм ранжирования

Балл = возможная дополнительная валовая маржа за 7 дней × коэффициент качества данных (0–1) × коэффициент срочности − операционная стоимость выполнения.

Оценки эффекта:

- Улучшение карточки = (целевой уровень конверсии − наблюдаемая конверсия) × просмотры × маржа на единицу × 7/30.
- Повторная покупка = количество клиентов с согласием × ожидаемый отклик × маржа заказа − затраты.
- Снижение скидки = недельные заказы × прирост маржи × доля сохранённого спроса − затраты.
- Остаток = ожидаемый дефицит единиц × маржа на единицу.

Пороговая конверсия 3,9%, отклик 27%, сохранение спроса 90% и коэффициенты качества 86/100, 78/100 и другие являются **демонстрационными допущениями**. Они не подтверждены на выборке. Балл качества входных данных не равен вероятности успешного увеличения выручки.

## План интеграции

### Входные API, только чтение

- GET /api/v1/merchant/products: идентификатор, категория, цена, себестоимость, скидка, остаток, полнота карточки.
- GET /api/v1/merchant/analytics?from=...&to=...: просмотры, заказы, выручка, агрегация по товару.
- GET /api/v1/merchant/promotions: активные скидки.
- GET /api/v1/merchant/segments: обезличенные RFM-агрегаты и численность группы с разрешённой коммуникацией.

Из контекста авторизации определяется конкретный продавец; клиент не передаёт tenant_id как доверенный источник.

### API рекомендаций

- GET /api/v1/recommendations/today: максимум три объекта с полями id, title, evidence, effects (оценка и диапазон), ranking_score, data_quality, assumptions, action_draft.
- POST /api/v1/recommendations/{id}/approval: решение approve/reject/postpone, reviewed_inputs, idempotency_key.
- GET /api/v1/recommendations/{id}/audit: причины, версии расчёта, решения пользователя.

Модули: приём агрегированных данных → валидация → расчёт экономических признаков → детекторы → ранжирование → черновик объяснения (LLM по фактам, опционально) → подтверждение → отдельный защищённый адаптер выполнения.

## Контроль качества и безопасное исполнение

- Минимальная выборка и возраст данных проверяются перед формированием рекомендации.
- Экономический расчёт и исходные признаки сохраняются для воспроизводимости.
- LLM не придумывает характеристики товара и не рассчитывает деньги: формулы выполняются детерминированно.
- При недостаточных данных система отказывается от конкретного прогноза.
- Перед реальным исполнением обязательно перепроверять цену, остатки, статус промо и согласия клиентов.
- Нельзя отправлять сообщения без разрешения на канал, соблюдения частотных лимитов и отдельного одобрения фермером.
- Одобренное решение защищено idempotency_key и аудиторским журналом; повторный запрос не дублирует действие.
- Эффективность проверяется пилотом и A/B-экспериментом: инкрементальная валовая маржа, охват, конверсия и жалобы. Учитывается сезонность.

## Ограничения MVP

Демонстрационная веб-версия не подключена к реальной платформе «Своё Родное», не использует реальных покупателей и не отправляет сообщения. В ней реализован автономный расчет правил и интерфейс принятия решений, а интеграция и генеративная часть описаны для следующего этапа.
